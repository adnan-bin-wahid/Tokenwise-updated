# TokenWise 0.6.1

Project overview retrieval, honest token accounting, and automatic carbon views.

## Install or Upgrade

1. Install `tokenwise-vscode-0.6.1.vsix` using **Extensions > ... > Install from VSIX...**.
2. Reload the editor window.
3. Run **TokenWise: Set Up Backend** and approve the managed backend update.
   Verified model downloads can be reused. Use **Retry Failed Step** for recovery.
4. Open your trusted local Python repository. Run **Enable Automatic Context**
   if it has not been configured on this computer.
5. Start a new Antigravity chat and ask your normal question.

If you use an existing checkout backend, update its source and restart its own
server instead. Reloading only the extension does not update Python retrieval.
Do not uninstall or remove all data just to upgrade.

## What Changed

- `Give me the full overview of my project` selects bounded documentation,
  package configuration, entry points, implementation, models, and tests instead
  of treating generic words as code identifiers.
- Disconnected modules can be represented. Large repositories show coverage
  warnings; initializer-only projects are identified as sparse scaffolds.
- The panel distinguishes retained source from formatted packed context.
  Keeping 17 source tokens in a 117-token bundle shows 0% source reduction and
  100 tokens of formatting overhead, not negative reduction.
- Automatic panels estimate CO2 before/after and signed energy/CO2 changes
  without delaying context retrieval. Disabled and failed estimates are visible.
- Carbon baselines use the same files and formatting. Values are approximate
  configured-scenario predictions, not actual Antigravity emissions.
- Bounded overview packing reserves space for multiple components and safely
  includes README code fences. Documentation edits invalidate exact caches.

## Verification and Limits

Regression tests cover broad versus focused intent, coverage, tiny projects,
candidate and token limits, documentation cache invalidation, formatting overhead,
carbon errors, signed increases, and delayed-result races. An isolated native
Windows verifier exercises real local weights, HTTP retrieval, and the compiled
extension carbon client; portable browser checks exercise result rendering.

Windows verification on October 5, 2026: 143 extension tests passed; 79 backend
tests ran with 78 passing and one file-symlink privilege skip; all six demo tests
passed. Real local-weight HTTP tests confirmed six-file overview coverage,
documentation cache invalidation, focused neural retrieval, activity-record
metrics, and zero savings for an initializer-only scaffold. Panel checks at
1280 and 390 pixels found no horizontal page overflow, overlapping stats, or
page-script errors; the copy-button message was verified. Antigravity's cloud
model was not called by these verifiers.

Automatic integration still depends on Antigravity following its rule or native
hook and allowing the local command. The plugin cannot create implementation
that is absent from the opened folder. Remote/virtual workspaces and native
macOS/Linux installation remain outside the verified Windows workflow.

See `README.md` for setup, recovery, privacy, and interpretation of these metrics.
