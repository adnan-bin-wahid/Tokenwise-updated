# TokenWise 0.6.0 - Windows Beta

Automatic Python repository context for Antigravity, with background indexing
and clearer, resumable setup. Normal users do not need Git, Node.js, F5, a GPU,
a separate TokenWise API key, or manual file selection.

## Download and Install

- [TokenWise 0.6.0 installer (.vsix)](https://github.com/adnan-bin-wahid/Tokenwise-updated/releases/download/v0.6.0/tokenwise-vscode-0.6.0.vsix)
- [Installer and full documentation (.zip)](https://github.com/adnan-bin-wahid/Tokenwise-updated/releases/download/v0.6.0/TokenWise-0.6.0.zip)
- [SHA-256 checksums](https://github.com/adnan-bin-wahid/Tokenwise-updated/releases/download/v0.6.0/SHA256SUMS.txt)

1. Install **64-bit Python 3.12** if needed, then restart Antigravity.
2. Install the VSIX through **Extensions > ... > Install from VSIX...**, then reload.
3. Open and trust a local Python repository. Run **TokenWise: Enable Automatic
   Context**, choose **Install Managed Backend**, approve setup, and confirm enabling.
4. Start a new Antigravity chat and enter your normal repository prompt.

Download the VSIX, not GitHub's source-code ZIP. First setup downloads about
1.35 GB of model weights plus CPU dependencies; allow about 10 GB free.

## What's New

- Configured, trusted Python repositories index on open, not on every prompt.
  Debounced saved-file changes update affected metadata. Periodic full
  reconciliation recovers missed events, including preserved-timestamp edits.
- Term counts, symbol locations, signatures, dependency graphs, and bounded
  tokenizer-specific token counts are reusable across different prompts.
  Exact request/content keys prevent similar prompts from sharing stale answers.
- Setup shows seven numbered steps with failed-stage recovery advice and
  **Retry Failed Step**. Validated dependency checkpoints and verified/partial
  downloads survive retries. Broken private environments can be recreated.
- **Retry Enable** handles repository setup failures without discarding unrelated
  rules or files. The complete guide includes a recovery table for every step.
- Managed update prompts explain when the Python backend also needs upgrading.
  Successful setup reconnects watchers to the newly registered backend.

## Upgrade Without Losing Caches

Finish active prompts, install the new VSIX, and reload the window. Select
**Update Backend** or run **TokenWise: Set Up Backend**. Approve setup and wait
for completion; verified model downloads are reused. After successful installation,
TokenWise stops the old managed backend only after verifying its process identity.
Existing repository links remain valid. Do not uninstall just to upgrade.

Existing checkout backends are not stopped or rewritten by setup. Update their
source and restart their own process yourself. Older backends retain conservative
retrieval, but need updating to use background indexing.

## Recovery and Support

Click **Retry Failed Step** after fixing the reported issue. If you dismissed
the notification or cancelled, run **Set Up Backend** again. Keep the same IDE
profile to reuse cached progress. See **Output > TokenWise Setup** for the full
error and **TokenWise: Open Setup Guide** for the step-by-step recovery table.
For configuration errors, fix the named file and choose **Retry Enable**.

Report issues with your OS, extension version, failed step, and sanitized logs
at [GitHub Issues](https://github.com/adnan-bin-wahid/Tokenwise-updated/issues).
Do not post credentials, private code, prompts, or `.tokenwise` records.

## Validation and Limits

Automated validation passed **121 extension tests** and the **69-test Python
suite** (one Windows file-symlink test skipped for missing privilege).
Coverage includes checkpoint recovery, interrupted downloads, upgrade ownership,
watcher lifecycle, exact-query separation, cache invalidation, and bounded context.

Windows native checks also passed: the actual VSIX installed and uninstalled in
an isolated Antigravity profile, stopping its owned backend and removing its
data while preserving unrelated code/settings. A fresh managed environment
installed real CPU dependencies, recovered a deliberate model-step failure,
reused three dependency checkpoints, loaded verified local neural weights, and
passed bounded HTTP retrieval and saved-edit invalidation. These checks did not
transfer the full model over the network or call Antigravity's cloud model.

A 1,000-file synthetic benchmark measured 0.559 ms median warm index/search
overhead and one AST reparse for a one-file edit. These numbers exclude neural
pruning and Antigravity's response; they are not end-to-end latency promises.

This remains a **Windows-tested beta**. Native macOS/Linux validation is pending;
remote and virtual workspaces are unsupported. Only saved disk files are indexed.
Missed file events can remain unseen until reconciliation, approximately two minutes.
Retrieval is local, but selected source enters your normal Antigravity model request.
Stable Antigravity relies on its agent following a rule/tool workflow, not guaranteed
native prompt interception. First model loading and neural pruning still take time.

Uninstall cleanup from 0.5.0 is retained. Complete removal may require a full IDE
restart. Customized files, unrelated settings, existing checkouts, Python itself,
and editor/OS-owned history are preserved; zero traces cannot be guaranteed.
