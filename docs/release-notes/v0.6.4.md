# TokenWise 0.6.4: Carbon Settings and Explicit Topic Exclusions

This patch fixes the two problems seen in the mixed session/invoice demonstration.

## Changes

- Zero optional model-size and input/output latency overrides use registered
  model features, rather than failing the carbon endpoint's positive-value
  validation. Blank GPU overrides are omitted. Real positive overrides and
  valid zero benchmark scores are preserved.
- Invalid scenario settings give an actionable error naming the setting.
  Prepared context remains usable; estimates are never fabricated on failure.
- Explicit contrasts such as `Explain session expiry, not invoice pricing`
  do not turn the excluded topic into positive retrieval keywords.
- Focused repository retrieval builds AST-based reference views that omit
  independent excluded units before neural pruning. Necessary helpers remain
  with warnings. Original files are untouched, and the original source counts
  remain the reduction baseline.
- Panels expose excluded topics and `scope_filter+...` methods. JSON exports
  include omitted-unit names. Exact queries and source snapshots remain isolated
  in the cache; a later invoice task still retrieves invoice source.

## Install or Upgrade

1. Download `tokenwise-vscode-0.6.4.vsix` from this release's assets and use
   **Install from VSIX...** in Antigravity.
2. Reload and run **TokenWise: Set Up Backend** to install its matching backend.
3. Run **TokenWise: Enable Automatic Context** in the Python folder.
4. Start a new chat and repeat the task. An old open result is not a new retrieval.

If setup fails, use **Retry Failed Step**. If carbon estimation reports a setting
error, repair that setting and reopen **Show Automatic Context** to retry it.
Validated model downloads can be reused; uninstalling is unnecessary.

Download `TokenWise-0.6.4.zip` for the installer, four runnable demo projects,
teacher guide, and verification record. `SHA256SUMS.txt` verifies the downloads.
No source checkout, Node.js, compilation, F5, or API key is required for normal
installation. Python 3.12 (64-bit) and initial download access are required.
Use this version's release link, not `/releases/latest`, which does not select
beta pre-releases. Previously published assets remain unchanged.

## Verification

- 161 extension tests passed; backend suite: 104 tests, 103 passed, one Windows
  symlink-privilege skip. Four demo applications and 28 tests passed.
- All six result views passed desktop and narrow browser checks, including
  carbon display, copy/export controls, and no overlapping statistics.
- A real-weight run retained session expiry/revocation and their tests while
  omitting the independent invoice units. Source counts were 701 to 439; the
  packed packet was 606 tokens. Both carbon estimates succeeded with the reported
  zero overrides, using registry features rather than fabricated predictions.
- That run's assertions completed, but Windows locked its temporary log during
  cleanup. A repeated run hit a local inference timeout. Owned processes were
  confirmed stopped and the temporary files subsequently removed. These checks
  do not certify cold-start latency or universal performance.

## Limits

Explicit contrast parsing is deliberately narrow; this is not arbitrary negation
understanding. Selected-source commands still run the neural model on the exact
captured source, and overview mode still describes repository structure. Neither
AST filtering nor neural relevance guarantees complete or executable excerpts.
Inspect originals before editing. CO2 values are approximate configured-scenario
estimates, not measured Antigravity emissions or net environmental savings.

Windows is the tested local platform. Native macOS/Linux, remote workspaces, and
live Antigravity cloud-answer quality are not certified by local verification.
